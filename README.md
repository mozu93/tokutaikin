# 特退金脱退 処理漏れ防止アプリ

アクサ生命の特退金（特定退職金共済制度）脱退案件で、**書類の未着**と、書類到着後の**WEB処理漏れ**を防ぐ Windows 向けのデスクトップアプリです。
Outlook に届く案件メールから受付簿を自動で作り、期限を過ぎた案件を画面で赤く知らせ、管理職へメールで通知します。

**バージョン: 1.1.0**（変更点は `RELEASE_NOTES.md`）

- 紹介: [`docs/introduction-slides.html`](docs/introduction-slides.html)（同僚向けの紹介スライド。ダウンロードしてブラウザで開く）
- 使い方: `MANUAL.md`（操作マニュアル）
- 仕様: `特退金脱退_処理漏れ防止アプリ_仕様書.html`

## 主な機能

- **メールの自動取り込み**: 指定した Outlook フォルダから、案件作成メール・処理完了メールを読み取り、案件番号ごとの受付簿を作る（起動時、設定した間隔、「今すぐ更新」）。会社名は半角カナの全角化と法人略称の読み替えをする。
- **状態の管理**: 書類待ち → （不備（補正待ち））→ 書類到着 → 処理済。
- **警告（営業日で数える。日数は設定で変更可）**:

  | 警告 | 条件 | 初期値 |
  |---|---|---|
  | 書類未着 | 状態が書類待ちで、案件作成日から基準日数以上 | 7営業日 |
  | 補正未着 | 不備を連絡した日から基準日数以上、補正書類が届かない | 7営業日 |
  | 未処理 | 書類到着日から基準日数以上、処理が済まない | 3営業日 |

  警告の案件は一覧で赤く表示し、トレイのアイコンとポップアップで知らせ、管理職2名へメールを送る（同じ案件・同じ種類は1日1回まで）。新しい警告が出たときに画面が隠れていれば、前面に出す。
- **保険会社への催促メール**: 書類待ちの案件を、案件作成日から設定した営業日（初期値7）ごとに、保険会社へ催促する。自動では送らず、確認の画面で送る案件を選んでから送信する（「送信」「今回は送らない」「後で」）。宛先・間隔・件名・本文の冒頭と末尾は設定で編集でき、宛先が空なら動かない。送信済みと「送らない」の記録は、通知履歴（`notify_log`）に残す。
- **サインイン切れの通知**: サインインが切れると、画面上部を黄色のバナーに変え、トレイのアイコンも警告の色にし、検知した日に1回ダイアログで案内する。再サインインして取り込みが成功すると消える。
- **かんたんインストールと自動更新**: インストーラー（`TokutaiApp-Setup-<版>.exe`）で、管理者権限なしに入れられる。新しい版が公開されると、アプリが通知し、「更新する」を押したときだけ更新する（取得先はこのリポジトリの Release のみ。SHA-256 が一致したインストーラーだけを実行する）。設定の「新しい版を自動で確認する」で切り替えられる。
- **書類到着の記録なし**: 書類到着日が空のまま、処理完了メールで処理済になった案件は、備考に「書類到着日の記録なし」と残す。
- **一覧の操作**: 絞り込み（未完了のみ・すべて・警告のみ・不備のみ）、検索（案件番号・会社名・備考）、見出しクリックで並び替え、見出しのドラッグで列の順番を変更（設定は次回も引き継ぐ）。
- **記録の操作**: 「書類が届いた」「不備を連絡した」「処理済にする」。Ctrl・Shiftキーで複数の案件を選ぶと、まとめて記録できる。そのほか（日付の修正、会社名・備考の編集、各種の取り消し、案件の追加、CSV出力、設定）は「その他」のメニューと行の右クリックから。
- **元に戻す**: 画面からの操作を、直前の10回まで「元に戻す」（Ctrl+Z）で戻せる。履歴はアプリを閉じると消える。メールの取り込みは戻せない。
- **保存期間**: 処理済の案件は、処理済日から1年（365日）たつと自動で削除する。未完了の案件は消さない。

## 起動

画面には PySide6（Qt for Python、LGPLv3）を使う。

```
pip install -r requirements.txt
python main.py              # 画面を表示して起動
python main.py --minimized  # トレイに最小化して起動（自動起動時の引数）
```

ウィンドウを閉じてもトレイに常駐し、メールの確認を続ける。終了するには、トレイのアイコンを右クリックして「終了」を選ぶ。
1台のPCに1つだけ起動する（2つ目を起動すると、すでにある画面が前面に出る）。受付簿はそのPCに置くので、複数のPCに入れる運用は想定していない。

## 初期設定

1. 「その他」→「設定」で、テナントID・クライアントID、Outlook のフォルダ名、管理職2名の宛先を入力する。
2. 「接続テスト」でサインインし、フォルダが見つかることを確認する。
3. 保険会社への催促メールを使う場合は、「保険会社の宛先」と「催促の間隔」、必要なら文面を設定する（宛先が空の間は動かない）。最初は、宛先を自分のアドレスにして試す。
4. 「Windows起動時に自動で起動する」をオンにして保存する。

### サインインで求める権限

Microsoft Entra ID に登録したアプリ（パブリッククライアント、リダイレクト URI は `http://localhost`）に、次の**委任**権限が必要。

| 権限 | 用途 |
|---|---|
| `Mail.Read` | 指定フォルダのメールの読み取り |
| `Mail.Send` | 管理職への警告メールと、保険会社への催促メールの送信（サインインした本人として送る） |

どちらも、サインインした利用者のメールボックス全体に対する権限になる（フォルダ単位では絞れない）。導入先の管理者には、この点を伝えて同意を得ること。
サインインの情報（トークン）は、Windows では DPAPI で暗号化して `token_cache.bin` に保存する。暗号化が使えない環境では、ログに警告を出したうえで暗号化せずに保存する。

## データの場所

`%APPDATA%\TokutaiApp\`（環境変数 `TOKUTAI_HOME` で変更可）

| ファイル | 内容 |
|---|---|
| `tokutai.db` | 受付簿・取り込み済みメール・通知履歴 |
| `settings.json` | 設定（一覧の絞り込み・並び順・列の順番も含む） |
| `token_cache.bin` | Microsoft のサインイン情報（暗号化。他人に渡さない） |
| `corporate_abbr.csv` | 法人略称表（編集可。列: abbr, formal, ambiguous） |
| `backup/` | 日次バックアップ（30世代） |
| `tokutai.log` | 取り込み・通知のログ |

### バックアップと復元

- バックアップは、起動時と、同期のたびに確認し、1日1回、`backup\tokutai_YYYYMMDD.db` として残す。常駐したまま再起動しなくても、毎日取れる。30世代（約1か月）を超えた古いものから削除する。
- 復元するときは、アプリを終了してから、戻したい日の `backup\tokutai_YYYYMMDD.db` を `tokutai.db` の名前でコピーして置き換え、アプリを起動する。
- 1年を過ぎた案件の削除や、誤った操作は、画面からは戻せない場合がある。必要な控えは、「その他」→「CSV出力」で書き出しておく。

```
python -m pytest tests -q
```

メール取得元を模擬したテストで、取り込み・警告・通知・まとめて処理・元に戻す・バックアップ・保存期間を確認している。

## インストーラーと自動更新

### 利用者向け（インストール）

GitHub の Release（https://github.com/mozu93/tokutaikin/releases）から、`TokutaiApp-Setup-<版>.exe` を取得して実行する。管理者権限は要らない。`%LOCALAPPDATA%\Programs\TokutaiApp` に入り、デスクトップとスタートメニューにショートカットができる。

インストーラーにはコード署名がないため、**実行する前に、ファイルが本物か SHA-256 で確かめる**。取得は、必ず上の公式の Release から行う。PowerShell で、取得したフォルダに移動して次を実行し、Release に添付した `TokutaiApp-Setup-<版>.exe.sha256` の値と一致したときだけ実行する。一致しないときは、実行せず、管理者に相談する。

```
Get-FileHash .\TokutaiApp-Setup-<版>.exe -Algorithm SHA256
```

値が一致したうえで、Windows の SmartScreen が警告した場合だけ、「詳細情報」→「実行」を選ぶ。

### 開発者向け（リリースの手順）

1. `tokutai/__init__.py` の `__version__` を上げ、`RELEASE_NOTES.md` に、その版の節（`## v1.2.3（2026-xx-xx）`）を書く。
2. 修正をまとめてコミットし、タグ `v<版>`（`__version__` と同じ値）を打って push する。
3. GitHub Actions（`.github/workflows/release.yml`）が、テスト → PyInstaller → Inno Setup の順に動き、`TokutaiApp-Setup-<版>.exe` と `.sha256` を Release に添付する。Release の説明には、`RELEASE_NOTES.md` のその版の節を使う。

Windows ランナーは、消費時間が2倍に数えられる。タグは、修正をまとめてから1回だけ打つ。タグと `__version__` が違うと、Actions は失敗する。

手元で試すとき:

```
pip install pyinstaller
pyinstaller --noconsole --onedir --name TokutaiApp --icon tokutai/data/app.ico --add-data "tokutai/data;tokutai/data" main.py
iscc /DAppVersion=1.1.0 installer\TokutaiApp.iss     # Inno Setup 6 が必要。出力: installer\Output\
```

アプリのアイコン（`tokutai/data/app.ico`）は、`python tools/make_icon.py` で作り直せる。

### 自動更新のしくみ

- `tokutai/updater.py` が、GitHub の最新の Release（`/releases/latest`）を調べ、今の版より新しく、インストーラーと `.sha256` が揃っていれば、更新の候補にする。下書き・先行リリースは対象外。
- 起動の約8秒後と、1日1回、確認する。通信に失敗しても、ログに残すだけで、画面には出さない。
- 「更新する」で、インストーラーを一時フォルダに取得し、SHA-256 を照合する。一致したときだけ、`/SILENT /CLOSEAPPLICATIONS` で実行し、アプリを終了する。インストーラーが、入れ替えたあとにアプリを起動し直す。
- インストールした exe のときだけ、自動更新できる。ソースから動かしているときは、通知だけ。
- 更新しても、データ（`%APPDATA%\TokutaiApp\`）は消えない。
- 固定の `AppId`（`installer/TokutaiApp.iss`）が、更新のときに「同じアプリ」と見分ける値になる。変更しないこと。

exe を他の人に配るときは、PySide6（LGPLv3）の条件に合わせて、ライセンス文を同梱し、Qt のライブラリを利用者が差し替えられる形で配る。そのため、1ファイルにまとめる `--onefile` ではなく、フォルダ形式の `--onedir` を使い、`dist\TokutaiApp` フォルダごと配る。条件の細部は、配布の前に確認すること。
