特退金脱退 処理漏れ防止アプリ 仕様書

2026-11-12 · たか

1. 目的と背景

アクサ生命の特退金（特定退職金共済制度）脱退案件で、書類の未着と、書類到着後のWEB処理漏れを防ぐアプリを作る。案件ごとの進み具合を自動で記録し、期限を過ぎた案件は警告表示と管理職への自動メールで知らせる。

  • 目的: 案件番号ごとの受付簿を自動で作り、書類到着日と処理済を記録して、滞留を早く見つける。
  • 利用者: 総務の担当者（書類到着の記録、画面での確認）と管理職（警告メールの受信）。
  • 対象外: 脱退事由（退職・死亡）の管理、脱退書類の内容確認、WEB処理そのものの自動化。

2. 業務フロー

案件作成メールが届くと受付簿に自動で登録され、処理完了メールが届くと処理済になる。アプリ上で人が操作するのは「書類が届いた」ボタンだけ。

書類が届かないまま7日たった場合と、書類が届いてからWEB処理が3日たっても進まない場合に、アプリは警告を出し、管理職へメールを送る。

3. 機能要件

アプリは次の8機能を持つ。

ID機能内容
F1受付簿の自動作成起動時と定期的に、指定したOutlookフォルダを読み取る。案件作成メールから案件番号・会社名・受信日を取り込み、受付簿に登録する。同じ案件番号は重複登録しない。
F2b不備の記録「不備を連絡した」ボタンで、不備を相手に連絡した日を記録する（書類到着日は空に戻る）。補正書類が届いたら「書類が届いた」を押すと不備は解消し、通常の流れに戻る。「不備を取り消す」で取り消せる。
F2eまとめて処理一覧でCtrl・Shiftキーを使って複数の案件を選ぶと、「書類が届いた」「不備を連絡した」「処理済にする」（全部が処理済のときは取り消し）を、選んだ案件にまとめて記録できる。日付は1回だけ入力し、実行前に件数を確認する。状態が合わない案件（処理済の案件への到着記録など）は対象外とし、その件数を知らせる。日付の修正・会社名と備考の編集・各種の取り消しは、1件ずつ行う。
F2f元に戻す「元に戻す」ボタン（Ctrl+Z）で、画面からの操作（到着・不備・処理済の記録と取り消し、日付の修正、会社名・備考の編集、案件の追加）を、直前の10回まで順に戻せる。まとめて処理した操作は1回として戻る。履歴はアプリを閉じると消える。操作のあとでメール取り込みなどにより同じ案件が変わっていたら、上書きしないため戻さず、その件数を知らせる。メールの取り込みそのものは戻せない。
F2c日付の修正「日付を修正」ボタン（行のダブルクリック、右クリックのメニューでも可）で、案件作成日・不備連絡日・書類到着日・処理済日をその場で直す。「あり」のチェックを外すと、その日付は空になる。
F2dCSV出力「CSV出力」ボタンで、絞り込みに関係なくすべての案件を、Excelで開ける形式（BOM付きUTF-8）で書き出す。1年保存で消える前の控えにも使える。
F2書類到着の記録「書類が届いた」ボタンで書類到着日を記録する。日付の初期値は当日で、変更できる。押し間違えは取り消せる。
F3処理済の自動判定処理完了メール（件名「アクサ生命：特退金制度申し込み」）の案件番号を受付簿と突き合わせ、処理済日を記録して状態を処理済にする。
F4警告表示基準日数を超えた案件を一覧で赤く表示し、画面上部に警告件数を出す。
F5管理職への自動メール警告対象の案件をまとめ、設定画面に登録した管理職2名の宛先へ自動送信する。同じ案件・同じ種類の通知は1日1回まで。
F6手動操作案件の手動追加、備考の編集、処理済の手動変更（メールを取り込めなかった場合の予備）。
F7設定接続情報、案件メールを入れるOutlookのフォルダ名、判定キーワード、管理職2名の宛先、基準日数、同期間隔、通知のオン・オフ。
F8自動起動Windowsへのサインイン時に自動で起動し、常駐する（7章）。

4. 状態遷移と警告ルール

案件は「書類待ち → 書類到着 → 処理済」の順に進み、未着7日・未処理3日を超えると警告になる。書類に不備があれば「不備（補正待ち）」にし、不備連絡から7営業日たっても補正書類が届かなければ警告にする（日数は設定で変更できる）。

状態入る条件次に進める操作
書類待ち案件作成メールを取り込んだ「書類が届いた」ボタン
書類到着ボタンで書類到着日を記録した処理完了メールの取り込み
処理済処理完了メールの案件番号が一致したなし
警告の種類条件初期値
書類未着状態が書類待ちで、案件作成日から基準日数以上たった7日
補正未着状態が不備（補正待ち）で、不備を連絡した日から基準日数以上たった7日
未処理状態が書類到着で、書類到着日から基準日数以上たった3日
  • 日数は営業日（土日・祝日を除く）で数える。
  • 処理済の案件は、処理済日から1年（365日）をすぎると、同期のときに受付簿から自動で削除する。未完了の案件は消さない。
  • 管理職への通知は、1案件・1種類につき1日1回まで。書類到着か処理済で警告が解消するまで、翌日以降も送る。
  • 処理完了メールが書類到着ボタンより先に届いた場合は、書類到着日を空のまま処理済にする。
  • 処理完了メールの案件番号が受付簿にない場合は、備考に「受付メール未確認」と付けて処理済で登録する。

6. メール連携仕様

メールはMicrosoft Graph APIで読み取り、管理職への通知も同じ接続で自動送信する。

  • 接続: 社内の別アプリと同じEntraアプリ登録（テナントID・クライアントID）を共用し、利用者の委任権限（Mail.Read、Mail.Send）で接続する。サインインは初回だけで、以降は暗号化して保存したトークンを更新して使う。
  • 読み取り対象: 設定画面に入力したOutlookのフォルダ名。受信トレイの下などのサブフォルダでも、名前から自動で探す（社内の別アプリと同じ方式）。見つからないときは画面に表示する。
  • 初回の取り込み範囲は過去60日（設定で変更可）。以降は前回の同期から1日さかのぼって取得する。
  • 同じメールを2回処理しない（メールIDを記録）。
種別件名の判定本文から取る項目受付簿への反映
案件作成「特退金脱退案件作成」を含む（空白は無視）案件番号、会社名新規登録（状態: 書類待ち）
処理完了「特退金制度申し込み」を含む案件番号処理済に更新
  • 案件番号: 本文の「案件番号：」の後ろにある、英字1文字と数字の並び（例: T900000000000001）。
  • 会社名: 案件作成メールの「上記書類を○○様へ」の○○を宛名として取り、半角カナを全角に直して、法人略称を正式名称に読み替える（例: ｻﾝﾌﾟﾙ (ｶ → サンプル株式会社）。
  • 法人略称は、全銀の法人略語に準じた対応表（12章）で読み替える。略称の付く位置は3通りに対応する。先頭は「カ）○○」で、正式名称を前に付ける（株式会社○○）。途中は「○○（カ）△△」で、その場で置き換える（○○株式会社△△）。末尾は「○○（カ」で、正式名称を後ろに付ける（○○株式会社）。末尾の形は、閉じ括弧がないことがある。
  • 照合は、長い略称を先に行う（例:「シホウ」を「シ」より先に）。小さい「ャ・ュ・ョ・ッ」は大きい字に直してから照合する。
  • 複数の法人格に当たる略称（イ・ザイ・シヤ・チユウ・ダイ）は、12章の表の先頭の法人格で読み替え、備考に「法人格は略称から推定（要確認）」と付ける。
  • 対応表にない略称は、そのまま残し、備考に「法人略称が未登録（要確認）」と付ける。取れない場合は空欄にする。どちらも画面で修正できる。
  • 対応表はデータファイルで持ち、略称を後から追加・修正できる。
  • 脱退事由は取り込まない。

7. 自動起動仕様

Windowsにサインインすると自動で起動し、タスクトレイに常駐して、人が操作しなくても取り込み・判定・通知を続ける。

  • 登録: 初回起動時にスタートアップへ登録する。設定画面のスイッチで、登録と解除を切り替えられる。
  • 起動時の動作: 最小化した状態で起動する。起動直後に「メール取り込み → 警告判定 → 管理職への通知」を1回実行する。
  • 定期実行: 起動後は設定した間隔（初期値30分）で同じ処理を繰り返す。
  • 常駐: ウィンドウを閉じてもアプリは終了しない。終了は、トレイのアイコンの右クリックから行う。
  • 警告の知らせ: 警告があるとトレイのアイコンの色を変え、新しい警告が出たときにポップアップで知らせる。
  • 二重起動の防止: すでに起動中なら新しく起動せず、既存の画面を前面に出す。
  • 取りこぼし対策: PCの停止中に届いたメールは、次の起動時に前回同期以降の分をまとめて取り込む。通知履歴を保存するので、再起動しても同じ通知を重ねて送らない。
  • 前提: メールの取り込みも警告メールの送信もアプリ自身が行うが、動くのはアプリが起動しているPCの上だけ。日数は営業日で数えるので、PCは平日の業務時間中に起動していれば足り、夜間・休日の常時稼働は要らない。停止中にたまった分は、次の起動時にまとめて処理して送る。

8. 画面仕様

画面は受付簿の一覧を中心にした1画面と、設定画面の2つ。

受付簿の画面

  • 上部のバナー: 「警告 N 件」を赤で、警告がなければ「警告なし」を緑で表示する。
  • ボタン: よく使う「書類が届いた」「不備を連絡した」「処理済にする」と「今すぐ更新」だけを並べ、選んだ案件の状態で押せるものだけを有効にする（不備の案件では「補正書類が届いた」、処理済の案件では「処理済を取り消す」に変わる）。そのほかの操作は「その他」のメニューと、行の右クリックにまとめる。
  • 絞り込み: 未完了のみ・すべて・警告のみ・不備のみ。選んだ絞り込みは次回の起動でも引き継ぐ。案件番号・会社名・備考で検索でき、検索中は「未完了のみ」でも処理済の案件を探せる。並び替え: 列の見出しをクリックすると、昇順 → 降順 → 標準の順に切り替わる（空の欄は常に最後）。選んだ並び順も次回の起動で引き継ぐ。
  • 一覧の列: 状態、警告、経過日数、案件番号、会社名、案件作成日、不備連絡日、書類到着日、処理済日、備考。見出しをドラッグすると列の順番を変えられ、変えた順番は次回の起動でも引き継ぐ。
  • 色: 警告の行は赤い背景、処理済の行は灰色の文字。
  • ボタン: 「書類が届いた」「到着を取り消す」「今すぐ更新」「案件を追加」「備考を編集」「設定」。
  • 「書類が届いた」: 一覧で案件を選んで押すと、日付の確認画面が開く。初期値は当日。
  • 下部のステータスバー: 最終更新の時刻、新規の件数、処理済の件数、送った通知の件数。

設定画面

  • 接続: テナントID、クライアントID（社内の別アプリと同じ値）、案件メールを入れるOutlookのフォルダ名。
  • 判定: 案件作成メールと処理完了メールの件名キーワード。
  • 警告: 未着の基準日数、未処理の基準日数、補正待ち（不備連絡後）の基準日数。
  • 通知: 警告メールの宛先（管理職1・管理職2の2欄）、通知のオン・オフ。
  • 動作: 同期の間隔、初回の取り込み日数、Windows起動時の自動起動。
  • 「接続テスト」ボタン: サインインと対象フォルダの検索を試し、結果を表示する。

9. 非機能要件とセキュリティ

アプリが触れるのは指定フォルダのメールと、管理職への通知メールの送信だけにする。

  • 権限: Microsoft Graphの委任権限は、メールの読み取り（Mail.Read）と送信（Mail.Send）の2つ。社内の別アプリがすでに同じ2つの権限を使っているため、同じアプリ登録を共用すれば、新しい登録や管理者の同意は要らない見込み。
  • 認証情報: パスワードは保存しない。サインイン後のトークンは、暗号化して利用者本人のフォルダに保存する（社内の別アプリと同じ方式）。
  • 保存するデータ: 案件番号、会社名、各日付、備考。メール本文は保存しない。
  • 通知先: 設定した管理職2名の宛先だけに送る。自動送信のため、宛先の設定は導入時に必ず確認する。
  • バックアップ: 1日1回、データベースのコピーを保存する。起動時と、同期のたび（日付が変わっていれば）に取るので、再起動しない常駐でも毎日残る。30世代まで残し、古いものから消す。
  • ログ: メールの取り込みと通知の成否をログファイルに残す。取り込みや送信に失敗したときは、画面にも表示する。
  • 利用台数: アプリは担当者のPC1台にだけ入れ、「書類が届いた」ボタンもその担当者が押す。受付簿はそのPCに置く。複数のPCに入れると受付簿が別々になり、警告メールも重複するため、想定しない。

導入手順は次の4つ。

  1. 社内の別アプリで使っているテナントIDとクライアントIDを確認する。新しいアプリ登録は作らず、Mail.ReadとMail.Sendがすでに許可されていることを確かめる。

  4. 自動起動のスイッチをオンにし、Windowsを再サインインして、トレイに常駐することを確認する。
